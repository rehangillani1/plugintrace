ACF stays offline unless you sign up, and leaves little behind

The FAQ makes a promise about data. In our lab, it kept it.

Advanced Custom Fields answers the privacy question in its own FAQ: ACF includes an optional email signup to receive plugin updates and news. No data is collected unless you choose to subscribe.

Our lab agrees. With default settings, ACF made no outside requests, set no cookies and loaded nothing from other sites, for visitors or for the admin. The signup is a banner on ACF's admin screens. Its code sends an email address to a form service at api.hsforms.com only when someone submits it (includes/admin/admin-email-opt-in-banner.php:234), and a comment in the same file says The email field is intentionally not prefilled to avoid accidental opt-ins.

Deleting ACF left 3 small settings (acf_version, acf_first_activated_version and acf_site_health) and the scheduled task acf_update_site_health_data. No tables.

Some plugins keep data on purpose, so nothing is lost if you reinstall. Look for a remove-data option in its settings before deleting. Shared libraries such as Action Scheduler may also be used by other plugins, so do not drop tables by hand without checking.

What to do

If you are choosing a plugin

We have not tested another custom fields and content types plugin yet. When choosing, compare the tags on this page with any alternative's report, and prefer plugins that clean up after themselves.

If you already use it

  • Nothing to change. With default settings it kept to itself in our test.

If you are removing it

  • Delete it from the Plugins screen rather than only deactivating it, so its own uninstall code runs. Take a backup first.

New reports and re-tests appear in our feed.

Quick answers

Does Advanced Custom Fields (ACF®) send data from my server?

No. With default settings it made no requests from the server to outside services in our test.

Does Advanced Custom Fields (ACF®) set cookies for visitors?

No. Our browser test found no cookies set for visitors with default settings.

Does Advanced Custom Fields (ACF®) load anything from other websites?

Not for visitors. Their browsers loaded nothing from other sites in our test.

Does Advanced Custom Fields (ACF®) remove its data when you delete it?

Not completely. After deleting it from the Plugins screen, 3 settings, 1 scheduled task remained in the database.

Does Advanced Custom Fields (ACF®) break page caching?

No. Public pages stayed cacheable: no new cookies or no-cache headers for visitors.

Evidence

Every finding above was recorded in one lab run with default settings on 2026-11-24: see how we test. The full machine-readable report is at /data/advanced-custom-fields.json. Plugin author and something looks wrong? Tell us and we will re-test.
